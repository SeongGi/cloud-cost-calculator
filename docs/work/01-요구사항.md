# 01. 요구사항 — 클라우드 비용 계산기

## 목표
- AWS / Azure / GCP 구성을 한국어 문장으로 설명하면 월 비용을 표·차트·계산기 화면으로 보여 준다.
- 개인 GitHub(SeongGi) 공개 저장소, 개인 도메인(seonggi.kr 하위)으로 공개한다.

## 하지 않을 것
- 외부 LLM 호출(OpenAI, Anthropic, Bedrock, OIUI 원본의 Jev 라우터 `api.typesafe.ai` 포함). LLM은 `localhost:11434` Ollama만.
- LLM이 단가·합계를 만들어 내는 것. LLM은 문장 → 항목/수량 변환만 한다.
- 회사 코드·데이터·문서·고객사명 참조, 비밀값 커밋.
- 예약/약정 할인, 프리 티어, 세금 계산(온디맨드 정가만, 화면에 명시).

## 성공 기준
1. 화면에서 질문 1개가 비용 카드로 나온다(로컬 Ollama).
2. AWS·Azure·GCP 각각 손계산 일치 케이스 3개(단가는 공식 가격 API/페이지와 대조).
3. 수량 기본값: 개수 1, 백만 단위 1, GB 100. 생략 시 적용하고 "가정"으로 표시.
4. 같은 입력이면 같은 합계(가격 스냅샷 고정, 계산은 결정적 코드).
5. 같은 서비스의 대안(DB 엔진 등)은 선택 상자, 합계에는 하나만.
6. 가격 기준일 표시, 주기적 갱신.
7. 라이트/다크, 본문 15px 이상, 390px 가로 넘침 0, 화면 글에 오류 문구 없음.
8. docker compose 실행, 기존 컨테이너·포트 무변경.
9. 첫 글자까지 시간, 완성 시간 실측 기록.

## 운영 위험
- 메모리 16GB: qwen3.5(6.6GB) + 컨테이너. 큰 모델(glm-4.7-flash 19GB) 사용 금지.
- AWS EC2 지역 가격 파일 약 300MB → 스트리밍 필터 필요.
- 로컬 모델 지연: 콜드 60~80초, 웜 약 10초(실측).
- 공개 사이트에서 LLM 남용 → 요청 제한 필요.

## 모델 실측 (2026-10-24, temperature 0, think=false, 도구 1개, 한국어 질문 3개)
| 모델 | 정확한 도구 호출 | 콜드 첫 응답 | 웜 완성 |
|---|---|---|---|
| qwen3.5:latest | 3/3 | 80.4s | 10.2s / 11.1s |
| batiai/qwen3.5-9b:q4 | 2/3 (타입을 engine에 넣음) | 64.2s | 9.5s / 10.3s |
| gemma4:e4b | 2/3 (GCP 질문에 도구 미호출) | 59.5s | 3.6s |
| glm-4.7-flash | 미측정: 19GB > 메모리 16GB | - | - |
→ **qwen3.5:latest 채택.**

## 열린 질문
- GCP: Cloud Billing Catalog API는 인증 없이 403. 인계 최종본에 이미 빌드된 가격표(39항목)가 있어 키가 필요 없다(2026-10-25 정정). 재생성이 필요할 때만 `gcloud auth print-access-token` 토큰을 쓴다(API 키 아님).
- 도메인 노출 방식(Cloudflare Tunnel 등)은 7단계에서 계획 보고 후 승인.

## 인계 자료 반영 (2026-10-24, 사용자 지시)
- 같은 계산기를 이전에 한 번 만들었다. 그 인계 자료(저장소 밖)를 출발점으로 삼되, 공개 저장소에는 일반 이름으로 재작성한 코드만 넣는다. 인계 폴더는 커밋·공개 금지.
- 확정 규칙(변경 금지): 월 비용 = 단가 × quantity_scale × hours × 수량, 단가는 가격표만, 기본 수량 개수 1·백만 1·GB 100, 사양 대안은 가장 싼 것 하나만 합산(함께 붙는 항목은 전부 합산), BigInt/Decimal 센트 계산, 기준일·가정 표시.
- 가격표(2026-10-25 정정): 인계 최종본(`handoff/final`)의 완성 JSON을 그대로 쓴다. AWS 46(기준일 2026-10-22), Azure 31(2026-10-23), GCP 39(2026-10-23), 각 3리전. 지금 단계에서는 재생성하지 않는다. 코드에 든 AWS 가격표를 공개 bulk 빌드 결과로 바꾸는 작업은 후순위다.
- 계산 규칙 정본: 최종본 `price_calculator.py`(일반 이름으로 다시 쓴 엔진이 같은 결과를 내야 함).
- 성공 기준 2 보강: 클라우드마다 손계산 3케이스(최종본 규칙·Decimal 0.5 올림 기준) + 정본 계산기와 기본값 합계 대조.
