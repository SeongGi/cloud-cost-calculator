## 외부 노출 확인 (2026-10-25)
- nginx 설정 뒤 도메인 요청이 gate까지 왔다. 다만 출발지가 OrbStack 게이트웨이 `192.168.171.1`로 보여서, nginx IP(192.168.1.230)로 허용하는 방식은 전부 403이었다. nginx가 보낸 X-Real-IP는 도착했다. 외부 스캐너 요청도 403으로 막혔다.
- 비밀 헤더 방식으로 바꾼 뒤 확인한 결과는 아래와 같다.

| 요청 | 결과 |
|---|---|
| 헤더 없음 | 403 |
| 틀린 값 | 403 |
| 빈 값 | 403 |
| 앞 20자만 맞음 | 403 |

### 앞단 프록시(NPMplus) 반영과 도메인 확인
- 원인: NPMplus는 Advanced 칸을 `server` 수준에 넣는다. 그런데 자체 `location /`에 `proxy_set_header`가 있어서 서버 수준의 헤더 줄은 무시됐다. 값 자체는 맞았다(해시 비교, 48자).
- 사용자 승인 후 cost.seonggi.kr(#26)만 수정했다.
  - Advanced 칸의 지시어를 `set $cost_proxy_secret`로 바꿨다. 값은 다시 입력하지 않았다.
  - Custom Location `~ /`를 추가했다(192.168.1.70:8095, 응답 버퍼링 끔, `proxy_set_header X-Proxy-Secret $cost_proxy_secret;`).
  - 처음에는 수식어 없는 `/`로 만들어 `duplicate location "/"` 오류가 났다. 그동안 이 호스트만 약 1분 Offline이었고, `~`로 바꿔 다시 Online이 됐다.
- 다른 호스트 영향: 수정 전후로 프록시 호스트 24개 전체에 요청을 보내 응답 코드를 비교했다. cost(403→200) 말고는 23개 모두 같았다.
- 도메인(https://cost.seonggi.kr) 화면 손계산은 7/7 일치했다. 텍스트 답은 첫 글자 4.6초, 완성 6.4초로 스트리밍이 정상이었다. 390px 가로 넘침 0, 콘솔 오류 0. gate 로그에는 `secret=ok`와 방문자 IP가 기록됐다.
