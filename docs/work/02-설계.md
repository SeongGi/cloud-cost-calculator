## 3. 에이전트

- `create_agent(model=ChatOllama(model=qwen3.5:latest, temperature=0, seed=0, reasoning=False, base_url=OLLAMA_BASE_URL), tools=[estimate_cost], middleware=[CopilotKitMiddleware()], system_prompt=짧은 한국어 지시)`
- `estimate_cost`는 `return_direct=True`: 도구 결과가 곧 답이다(두 번째 LLM 호출 생략 → 약 10초 단축). 화면은 카드가 담당.
- 도구가 필요 없는 질문(인사, 범위 밖)은 모델이 짧은 텍스트로 답한다.
- 인자 방어: `items`가 문자열(괄호 빠진 JSON 포함)로 오면 파싱 시도 → 실패 시 도구가 오류 객체 반환(화면에 명확한 안내, 예외 삼킴 없음).
- `OLLAMA_BASE_URL`이 localhost/host.docker.internal/사설 주소가 아니면 기동 실패(외부 LLM 차단 가드).
- 동시성: Ollama 직렬 처리를 감안해 프론트 rate limit 켬(IP당 분당 10회).

### 도구 인자 스키마 (인계 기준으로 교체, 2026-10-24)
```
estimate_cost(
  cloud: "aws"|"azure"|"gcp",
  region?: str,                       # 기본 서울(ap-northeast-2 / koreacentral / asia-northeast3)
  items: [{
    service: str,                     # 가격표 별칭(aliases)으로 해석. 예: "ec2", "rds", "s3", "virtual machines", "cloud sql"
    spec?: str,                       # 사양 단서. 예: "t3.medium", "postgres", "D2s v5", "e2-standard-2"
    count?: int, gb?: int, million?: int   # 단위별 수량. 생략 시 기본값(개수 1, GB 100, 백만 1)
  }]
)
```
모델은 서비스 이름·사양 단서·수량만 넣는다. 항목 선택과 단가는 코드가 한다.

## 4. 계산 규칙 (인계 문서 2절 그대로, 바꾸지 않음)

- 가격표: 클라우드마다 `{key: {service, label{ko,en,ja}, quantity_unit, per, quantity_scale, hours, slider, prices{region: {usd, unit, ...}}}}`. 단가는 가격표 값만 쓴다.
- 월 비용(센트) = round_half_up(단가 × quantity_scale × hours × 수량 × 100). 정수/Decimal 연산(서버 Python `Decimal`, 화면 BigInt). 부동소수 금지.
- 서비스 하나를 고르면 그 서비스의 가격표 항목이 모두 줄이 된다(함께 붙는 항목: ALB 시간+LCU, RDS 인스턴스+스토리지, S3 저장+요청 등 전부 합산).
- **사양 대안 묶음**(family: EC2/VM 크기, RDS·Cloud SQL·Azure DB 엔진×크기, Aurora, 캐시 등급)은 한 줄로 묶고 합계에는 하나만. 기본 선택은 가장 싼 것. `spec`이 주어지면 그 단서와 맞는 항목(여럿이면 가장 싼 것)을 선택. 가격표에 없는 사양이면 "가격표에 없음"으로 표시하고 합계에서 뺀다(선택 상자로 대안을 고르면 포함).
- 기본 수량(qty_rule): 단위가 `million_*`이면 1, `gb`이면 100, 그 외(count, lcu, vcpu, memory_gb …) 1. 슬라이더 범위·step에 맞춘다. 사용자 수량이 없으면 "가정"으로 표시.
- 사용자 수량 적용: `count` → 해당 서비스의 개수 단위 줄(대안 묶음 줄 포함), `gb` → gb 단위 줄, `million` → million_* 단위 줄.
- 리전: 가격표 리전(AWS ap-northeast-2/ap-northeast-1/us-east-1, Azure koreacentral/japaneast/eastus, GCP asia-northeast3/asia-northeast1/us-central1). 그 밖이면 서울로 계산하고 "요청 리전 미지원 → 서울 기준" 표시.
- 별칭에 없는 서비스는 `excluded`(가격표에 없음)로 화면에 표시, 합계 제외.
- 결정성: 같은 가격표 기준일 + 같은 정규화 인자 → 같은 합계. 줄 정렬은 가격표 키 순.

### 도구 결과(JSON)
```
{ cloud, region, region_label, requested_region?, currency:"USD", as_of, source,
  lines:[{ id, service, group, key, label, usd, unit, quantity_unit, scale, hours, slider,
           qty, default_qty, assumed, alternatives?:[{key,label,usd,scale,hours}], missing_spec?, subtotal_cents }],
  excluded:[{service, reason}], notes:[...], total_cents }
```

## 5. 가격표 빌더

- 조회 명세(spec JSON: 항목 키, 라벨, 단위, 필터)는 인계 자료의 명세를 데이터로 가져온다(회사 식별자 없음 확인). 빌더 코드는 새로 작성.
- 위치: `apps/agent/pricing/specs/{aws,azure,gcp}_spec.json`, 결과 `apps/agent/pricing/catalogs/{aws,azure,gcp}.json`(공개 가격, 커밋). 컨테이너는 볼륨 `/data/catalogs`가 있으면 그것을 우선.
- **AWS**: 공개 bulk 파일. `region_index.json` → 지역별 offer JSON을 `ijson`으로 스트리밍(EC2 약 300MB도 메모리 일정). 명세 필터(JSON 속성명 = Query API 필드명)와 정확히 일치하는 상품 1개, OnDemand 조건 1개, beginRange 0 구간, 단위·productFamily·regionCode 검증. 기존 46항목(기준일 2026-10-22) 단가와 대조.
- **Azure**: Retail Prices API(인증 없음), 명세의 `$filter`, 정확히 1개 미터, `allow_non_primary`·`global_price`·`tier_min` 규칙. 기존 31항목×3리전과 대조.
- **GCP**: Cloud Billing Catalog API. 재생성할 때만 `GCP_ACCESS_TOKEN`(`gcloud auth print-access-token`, 약 1시간 유효) 필요. 구성요소마다 SKU 1개, 첫 유료 계층 단가, vCPU+RAM은 단가×multiplier 합.
- **현재 운영(2026-10-25 정정)**: 위 빌더로 재생성하지 않고, 인계 최종본의 완성 가격표 3개(`pricing/catalogs/{aws,azure,gcp}.json`)를 그대로 쓴다. AWS 최종본은 Query API로 만든 것이고, 공개 bulk 빌더(`build_aws.py`, `make prices`)로 다시 만든 결과와 단가가 138/138 같다. 코드에 든 가격표를 bulk 빌드 결과로 바꾸는 것은 후순위다.
- GCP 액세스 토큰은 약 1시간 뒤 만료된다. 그래서 GCP는 매일 자동 갱신이 되지 않고, 손으로 다시 만들 때만 쓴다.
- 출처 표기는 가격표의 `source` 값에서 정한다(Query API / bulk / Retail Prices / Cloud Billing Catalog).
- 기준일: 가격표의 `as_of`(빌드 날짜), AWS는 offer `publicationDate`도 항목별 보존.
- 갱신: `PRICE_REFRESH=true`일 때만 에이전트 백그라운드 스레드가 매일 04:00 KST에 AWS/Azure(토큰 있으면 GCP) 재빌드 → 검증 통과 시에만 교체, 실패 시 이전 가격표 유지. **기본값은 꺼짐**이고, 꺼져 있으면 볼륨에 예전 갱신본이 있어도 코드에 든 가격표만 읽는다. 다시 켤 때는 볼륨의 예전 갱신본(기준일 2026-10-24, bulk 출처)이 코드의 가격표보다 새것으로 보여 먼저 쓰이므로, 켜기 전에 `catalogs` 볼륨을 비운다. `make prices`/`build_*`를 로컬에서 실행하면 저장소의 가격표 JSON을 덮어쓴다.

## 9. 1차 검토 반영 (필수 7건 + 권고)

1. **체크포인터**: `create_agent(..., checkpointer=BoundedMemorySaver(max_threads=200))` 유지, `langgraph==1.0.7` 고정 유지.
2. **모델이 보는 도구 = estimate_cost 1개**: 런타임 옵션에서 `a2ui`, `openGenerativeUI`, `mcpApps` 제거, providers의 `a2ui`/`openGenerativeUI`/activity renderer 제거, 예제 훅(`useFrontendTool`/`useComponent`/`useHumanInTheLoop`) 삭제. 에이전트 테스트에서 모델 바인딩 도구 이름 목록이 `["estimate_cost"]`임을 확인(미들웨어 래핑 후 요청을 가로채는 가짜 모델로 측정).
3. **크기 기본값**(코드 상수, 가정으로 표시):
   | 클라우드 | vm | database |
   |---|---|---|
   | AWS | t3.medium | db.t3.medium |
   | Azure | Standard_D2s_v5 | GP_Standard_D2ds_v5 (2 vCore) |
   | GCP | e2-standard-2 | db-custom-2-8192 (2 vCPU, 8GB) |
   database 엔진 기본값은 postgresql.
4. **대안 합산 방지**: 정규화 단계에서 database 항목 중 (size, count, storage_gb)가 같고 engine만 다른 항목은 1줄로 합치고, 첫 엔진을 selected, 나머지는 alternatives 앞쪽에 둔다. 모든 database 줄은 그 지역에서 같은 size가 있는 엔진 전부를 alternatives로 갖는다. 같은 size가 없는 엔진(예: Aurora db.t3.micro)은 제외하고 notes에 "해당 크기 미지원" 기록. Aurora(Standard) I/O는 `io_requests_million`(기본 1, 가정 표시) × 백만 요청 단가로 포함.
5. **AWS CSV**: 앞 5줄 메타데이터(`Publication Date`, `Version` 읽음) 뒤 6번째 줄이 헤더. 실측 헤더명 사용: `TermType=OnDemand`, `Product Family=Compute Instance`, `Location Type=AWS Region`, `Operating System=Linux`, `Tenancy=Shared`, `Pre Installed S/W=NA`, `CapacityStatus=Used`, `License Model=No License required`; EBS는 `Product Family=Storage`, `Volume API Name=gp3`(헤더 실측 후 확정). `csv.reader`로 한 줄씩 → 메모리 일정.
6. **GCP VM/Cloud SQL 산식**: Catalog API는 vCPU-시간·RAM GB-시간 SKU를 준다. 머신 타입 사양(vCPU·메모리)은 공개 문서 기반 사양표를 코드에 둔다(단가 아님, 출처 URL 주석). 월 = (vCPU × vCPU 단가 + 메모리GB × RAM 단가) × 730 × count. e2-micro/small/medium(공유 코어)은 별도 SKU가 있으면 그것을, 없으면 지원하지 않음 오류. Cloud SQL `db-custom-{vCPU}-{MB}`도 같은 방식 + 스토리지 SSD GB-월.
7. **Functions 범위**: requests_million(기본 1) × 백만 요청 단가 + GB-초(기본 메모리 128MB, 평균 100ms, 가정 표시) 계층 단가. 프리티어 무료 요청/GB-초는 제외.

권고 반영:
- Ollama 주소 가드: 호스트가 `localhost`, `127.0.0.1`, `::1`, `host.docker.internal` 중 하나가 아니면 기동 실패.
- 결정성 정의: "같은 가격 기준일 + 같은 정규화 인자 → 같은 합계". 인자 정규화(기본값 채움, database 병합, 항목 정렬 없음 — 사용자 순서 유지). 같은 질문 3회 반복 실측을 04-검증에 기록.
- return_direct 동작(TOOL_CALL_RESULT 전달, 다음 턴 정상)은 1단계 데모에서 실측. 카드에서 `JSON.parse` 실패 시 "결과 형식 오류" 안내(삼키지 않음).
- `langchain-ollama` 의존성 추가, 버전에서 `reasoning`/`seed`/`keep_alive`/`num_ctx` 지원 확인. 기동 시 예열 1회, `keep_alive=30m`, `num_ctx=8192`.
- 계층표: 각 미터의 API 계층을 그대로 사용(Azure 이그레스 첫 100GB 0원 구간 포함). AWS 전역 프리티어(Global 100GB)는 별도 SKU라 제외. 화면 notes에 명시.

- 요청 제한: 키는 `cf-connecting-ip` → `x-real-ip` → `x-forwarded-for` 순. 에이전트 동시 실행 상한 2(세마포어), 초과 시 "대기 중" 안내.

## 10. 2차 검토 반영 — 8095 직접 노출 대책

- 8095 비어 있음 실측(2026-10-24, `lsof -iTCP:8095 -sTCP:LISTEN` 결과 없음, 컨테이너 포트 매핑 없음).
- compose에 경량 `gate`(nginx:alpine) 서비스를 둔다. `gate`만 `0.0.0.0:8095`를 열고, `app`·`agent`는 내부 네트워크 전용.
  - `allow <외부 nginx IP>; allow 127.0.0.1; deny all;` — 외부 nginx IP는 `.env`의 `TRUSTED_PROXY_IP`로 주입(사용자에게 확인). 미설정이면 기동 시 경고하고 loopback만 허용(안전 기본값).
  - `set_real_ip_from <TRUSTED_PROXY_IP>; real_ip_header X-Real-IP;` → 신뢰한 프록시에서 온 경우에만 헤더 사용. gate가 app에 `X-Real-IP $remote_addr`를 덮어써 전달.
  - `proxy_buffering off; proxy_read_timeout 300s;`, `limit_req zone=ip 10r/m burst=5`.
  - OrbStack 포트 공개가 원래 출발지 IP를 보존하는지 5단계에서 실측. 보존하지 않으면 gate의 allow 대신 macOS pf 규칙을 사용자 승인 후 적용.
- app의 요청 제한 키는 gate가 넣은 `X-Real-IP`만 사용(`cf-connecting-ip` 제거). IP와 무관한 전역 상한도 둔다: 에이전트 동시 실행 2, 대기 4 초과 시 429 "잠시 후 다시".
- 사용자 nginx 권장 설정(SSE): `proxy_buffering off`, `proxy_read_timeout 300s`.

## 12. 외부 노출 (2026-10-25, 사용자 승인: 비밀 헤더 방식)
- 경로: 인터넷 → 앞단 nginx(192.168.1.230, TLS) → 맥미니 192.168.1.70:8095 → gate → app.
- 실측: OrbStack 포트 공개는 모든 연결의 출발지를 `192.168.171.1`로 바꾼다. nginx IP로 허용하면 전부 403이었다.
- 결정: nginx가 `X-Proxy-Secret`(48자 무작위, `.env`의 `PROXY_SECRET`, 커밋 안 함)을 보낸다. gate는 신뢰 peer(`192.168.171.1`)이면서 비밀값이 정확히 같을 때만 통과시키고, 그때만 `X-Real-IP`를 방문자 IP로 쓴다(요청 제한 키).
- 시작 검사: `TRUSTED_PROXY_IP`가 루프백이 아닌데 `PROXY_SECRET`가 32자 미만이거나 영문·숫자가 아니면 gate가 시작을 거부한다.
- 맥 방화벽(pf) 같은 시스템 설정은 바꾸지 않는다. nginx와 맥미니 사이 구간은 LAN 평문 HTTP다(가정용 LAN이라 허용).

## 13. Gemini 우선 + 로컬 대체, 관리자 페이지 (2026-10-25, 사용자 승인)
- 규칙 변경: 처음 정한 "로컬 Ollama만"을 사용자가 바꿨다. 이제 Gemini(AI Studio 키)를 기본으로 쓰고, 한도 초과·오류·시간 초과가 나면 로컬 qwen3.5가 같은 요청에 답한다. 가격 규칙은 그대로다(LLM은 항목과 수량만 뽑고, 단가와 계산은 코드가 한다).
- 구현:
  - 에이전트는 로컬 모델로 만든다. `LLMRouter` 미들웨어가 모델을 부를 때마다 Gemini로 바꿔 시도하고, 예외가 나면 원래 요청을 로컬로 넘긴다.
  - 한도 초과면 10분, 그 밖의 오류면 2분 동안 Gemini를 건너뛴다.
  - 키나 모델을 바꾸면 쉬는 시간을 지운다.
  - Gemini 클라이언트는 재시도 0회, 30초 시간 제한으로 둔다. Gemini가 설정돼 있으면 시작할 때 로컬 모델을 미리 올리지 않는다(메모리 절약).
- 설정 저장: `/data/settings/llm.json`(볼륨, 권한 600, 원자적 교체). `.env`의 `GEMINI_API_KEY`는 저장된 설정이 없을 때만 쓴다.
- 관리자 경로: 공개 gate → oauth2-proxy(Google, 허용 이메일 파일) → gate 내부 8081(공개 안 됨, `X-Admin-Gate` 비밀 추가) → 앱 `/admin`, `/api/admin/*` → 에이전트 `/admin/*`(`X-Admin-Token`).
  - 공개 경로에서는 gate가 `X-Admin-Gate`, `X-Forwarded-Email`, `X-Forwarded-User`를 지운다.
  - 앱 API는 허용한 4개 경로와 메서드만 넘긴다.
  - 에이전트의 문서 경로(/docs, /openapi.json)는 끈다.
- 다른 개인 프로젝트(gcp-checklist, salim-helper)와 같은 oauth2-proxy v7.10.0과 같은 Google OAuth 클라이언트를 쓴다.
