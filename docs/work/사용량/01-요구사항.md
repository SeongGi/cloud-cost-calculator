# 01. 요구사항: 관리자 페이지 사용량

## 목표
- 관리자가 "사람들이 계산기를 얼마나 썼는지"를 `/admin`에서 본다: 기간별 질문 수, 방문자 수, 대화 수, 일별 추이, 클라우드·서비스별 계산 수, 실패 건수.
- 기록은 재시작·재배포 뒤에도 남는다.

## 하지 않을 것
- 질문 원문, 답변 원문, 사용자가 적은 사양 문자열(spec) 저장. 남기는 것은 시각과 가격표의 서비스 키, 결과 상태 같은 메타데이터뿐이다.
- IP 원문 저장. 방문자는 비밀 salt로 만든 HMAC 해시(앞 16자리)로만 센다.
- 페이지 방문(조회수) 분석, 외부 분석 서비스 연동, 지역·브라우저 통계.
- 사용량 데이터 내보내기·삭제 화면.

## 용어
- 질문: 레이트 리밋을 통과해 agent로 간 `agent/run` 한 건. "다시 시도"도 1건이다.
- 방문자: 질문을 보낸 서로 다른 IP 해시 수. 제한에 걸린 방문자는 따로 센다.
- 대화: 서로 다른 threadId 해시 수.
- 계산: `estimate_cost` 도구 호출 한 건(한 질문에 클라우드 여러 개면 여러 건). 연결 질문에서 시스템이 반대편에 덧붙인 VPN 계산은 빼고 센다.
- 실패: 계산 오류, 답변 실패, agent 혼잡 거절을 건수로 센다(비율은 내지 않는다).

## 성공 기준
1. 질문 한 건마다 질문 기록 1줄, 계산마다 계산 기록 1줄이 저장된다. 레이트 리밋에 걸린 방문자는 리밋 창마다 1회 "제한"으로 따로 센다.
2. 저장된 행 어디에도 질문 문장, spec, IP 원문이 없다(테스트로 확인).
3. `/admin`에 사용량 카드가 생기고 7·30·90일을 고를 수 있다. 수치는 손으로 넣은 기록과 일치한다(테스트로 확인).
4. 날짜는 한국 시간(KST) 기준으로 나눈다.
5. 기록 실패(디스크 오류 등)는 방문자의 답변을 막지 않는다.
6. 1년(400일)이 지난 기록은 지운다.
7. 기존 테스트(pytest·vitest)가 모두 통과한다.

## 운영 위험
- 기록 파일은 settings 볼륨에 있다. 볼륨을 지우면 사용량도 사라진다.
- 배포 전까지 쌓인 사용량은 gate 접속 로그에만 있어 이 기능으로 옮기지 않는다.
